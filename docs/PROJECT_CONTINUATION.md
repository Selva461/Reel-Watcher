## 1. What the project is

Reel Shelf (repo `Selva461/Reel-Watcher`) is an Android app that keeps the user's saved Instagram reels (and YouTube Shorts), reads them locally, makes notes, and lets the user search them and build a watchlist of titles. Local-first: on-phone models, no mandatory paid or cloud service, no login to Instagram, the user taps in Chrome themselves. `AGENTS.md` is partly stale (it still says "Windows edition"); the Android app is the active product. `README.md` is stale too. Both are deliberately untouched until the owner says to reconcile them.

Architecture [V, from the code and AGENTS.md]:
- **Android shell** `android/app-shell/app/src/main/`: a WebView loads `assets/local/` (plain JavaScript, no build step, no React or TypeScript, CSP forbids inline scripts): `local.js` (screens, run loop, library load and save), `notes.js`, `library.js` (search helpers, topics), `search.js`, `catalog.js` (watchlist), `shots.js` (screenshots), `titles.js`, `verify.js`, `home.js`, `watch.js`. The page talks to Java through `window.RN` (`LocalBridge.java`, 81 `@JavascriptInterface` methods counted 2026-11-20, trusted only for the built-in page).
- **Java** `java/app/reelshelf/`: `LibraryFile` (reels.json and shots.json: temp file, fsync, `.bak`, lock when unreadable, `.bad-TIME` set-aside, revision), `SharedQueue`, `SettingsPatch`, `LocalBridge`, `MainActivity`, `ShareActivity`, `WorkService`, `NightRun` (the nightly run uses a hidden headless WebView running the same page), `NightlyCheck`, `VerifyJob`, `TitleVerifier`, `TitleMatch`, `WebLookup`, `LocalModel` (LiteRT-LM: Qwen 2.5 1.5B, Gemma 4 E2B/E4B), `ScreenshotReader` (ML Kit OCR, Latin), `ReelVideo`, `SpeechModel` (Vosk, English). Added since 1.3.11 (all on the default branch now): `MediaBatch`, `MediaCopy`, `SharedItems` (shared pictures and videos copied in the background), `LibraryBackup`, `BackupNow`, `RestoreNow`, `KeptFiles` (backup, restore, files kept for safety), `TempSweep`, `TempSweeper` (temp-file sweep), `ModelCatalog`, `ModelVerifier`, `ModelZip`, `ModelCheck` (pinned models, verified downloads, check of models already on the phone), `NightGuard` (night run and open app no longer overlap), `Host`.
- **Storage** in the app's files folder: `reels.json`, `shots.json`, `verify-results.json`, `models/`, `speech/`, `shot-inbox/`, `video-inbox/`; since S4 and 5a also `share-staging/`, `backup-work/`, `backup-check/`, `restore-staging/` and the files kept for safety (`*.bad-*`, `*.before-restore-*`); settings (including optional user-entered TMDB/OMDb keys) and the share queue in SharedPreferences. Backups from "Back up now" are ZIP files saved to `Downloads/ReelShelf` (Android 10+) or to the app's own external Download folder (Android 8 and 9, which uninstalling deletes). `allowBackup` is false.
- **Python engine** `src/reel_watcher/` and `webapp/`: the older PC edition (SQLite library). The Android app does not start it. Tests in `tests/` (Python; the "phone harness" drives the page in Chromium with a fake `window.RN`: `tests/test_phone_app.py`) and JUnit 4 in `android/app-shell/app/src/test/`.
- **CI** `.github/workflows/`: `tests.yml` (uv run pytest and pip-audit; on push and pull_request), `android-ci.yml` (JUnit and assembleRelease on PRs that touch `android/app-shell`), `android-apk.yml` (a push to the default branch that touches `android/app-shell/**` or the file itself builds and tests the APK and keeps it as the workflow artifact `ReelShelf-apk`; since R5 (#40, merged 2026-11-20) it publishes release `v<versionName>` and moves `apk-latest` ONLY when run by hand on the default branch: GitHub Actions > Android APK > Run workflow; the repository is public).

## 6. Known bugs and technical debt

Verified by measurement or code reading earlier in this project (desktop Chromium or JVM, never a phone):
- **Large-library memory**: `LibraryFile.valid()` and `VerifyJob.run` build a full JSON tree of the library (30-60 MB at 5,000-10,000 reels); a 256 MB-heap JVM ran out of memory at 60 MB. Not measured on a device. (P4)
- **No real backup or restore**: the existing export is lossy and cannot be imported; `allowBackup` is false; uninstall loses everything. (S4) **Status 2026-11-20: S4-1 to S4-4 (backup, restore, files kept for safety) are merged, not checked on a phone; on Android 8 and 9 the backup file sits in the app's own folder and is deleted with the app.**

## 8. Data-integrity and security requirements (must hold)

- Never silently delete or replace user data. A damaged or older file is set aside (renamed), never removed. Writes: temp file, fsync, rename. Reels and screenshots go through `LibraryFile` and its revision protocol; a stale page's save is refused. The share queue is acknowledged by id only after a successful save.
- Local-first. No mandatory paid API or cloud LLM. No hardcoded or bundled API keys (optional user-entered TMDB/OMDb keys are allowed). Never use `--source apify`. No Instagram login, cookies or automation. Model downloads only from the allowed host. No em dash characters in Python sources (a test enforces it). Always `encoding="utf-8"` for text files.
- No real reel data in tests or examples: placeholders and generated data only.
- Permission or manifest changes must be documented and approved if sensitive. The bridge is for the built-in page only; escape every interpolated HTML value.
- Never claim device testing that was not done. Device checks are run by the owner (rows in `TESTING.md`).
